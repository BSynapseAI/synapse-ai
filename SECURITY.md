# Security Policy

## Overview

Security is an important part of Synapse AI development. We take reports of security vulnerabilities seriously and appreciate responsible disclosure.

## Supported Versions

Security fixes are generally applied to actively maintained versions of Synapse AI.

As the project evolves, supported versions may change.

## Reporting a Vulnerability

If you discover a security vulnerability in Synapse AI, please report it privately rather than creating a public GitHub issue.

For security-related reports, contact:

**[support@bsynapseai.com](mailto:support@bsynapseai.com)**

Please include:

* A clear description of the vulnerability.
* Steps required to reproduce the issue.
* The potential impact.
* Relevant logs, screenshots, or proof-of-concept information when safe to provide.
* Any suggested mitigation, if available.

Please do not include passwords, API keys, access tokens, or other sensitive credentials in your report.

## Responsible Disclosure

We ask security researchers and contributors to:

* Avoid accessing or modifying data that does not belong to them.
* Avoid disrupting Synapse AI services or infrastructure.
* Avoid publicly disclosing a vulnerability before it has been reviewed.
* Provide sufficient information to reproduce and understand the issue.

We will review legitimate reports and work toward addressing confirmed vulnerabilities appropriately.

## Security of Contributions

Contributors must never commit:

* API keys
* Access tokens
* Passwords
* Private keys
* Database credentials
* `.env` files containing secrets
* Personal or confidential information
* Production credentials

If sensitive information is accidentally committed, report it immediately and rotate the affected credentials.

## Scope

This policy applies to security vulnerabilities affecting the Synapse AI project and its publicly available repository components.

Thank you to everyone who helps improve the security of Synapse AI.
